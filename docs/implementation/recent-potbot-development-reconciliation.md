### Reading the status column

- **Mapped:** requirements exist in companion sources; the summary roadmap needed traceability or a precise gate.
- **Partial:** the source describes a foundation and explicitly leaves integration or capabilities incomplete.
- **Conflict:** two requirements/descriptions need an explicit resolution; the newer summary must not silently discard the original requirement.
- **Unverified:** a referenced component or acceptance result was not located in the inspected sources. This is a bounded finding, not proof that no implementation exists anywhere.
- **Planned:** an existing programme explicitly remains proposed or not started.

These are audit classifications, not replacements for the existing stage status vocabulary. Historical test statements, documentation and saved qualification emails are not current CI evidence.

## 6. Implementation ordering and closure

1. **Close planning conflicts and inventory holes.** Apply RD26 and the service chronology correction; record the resolved RD13 read-only/operator-unlock policy and RD15 OS-native-watcher/loss-reconciliation policy as canonical qualification requirements. Locate or implement S12/S36, map saved operation-catalogue requirements and add MG/original P/E stages to the master inventory. Do not declare U00 complete while binary variants, unavailable P6 sources, issues or CI evidence remain unreconciled.
2. **Qualify foundation and lifecycle boundaries.** Continue the previous worker/SYN gates alongside RD11–RD17, context migration/host/protocol coverage and R6.1 accounting. Use one existing database/job/Cog authority, with explicit uncertain-effect handling.
3. **Deliver complete useful feature slices.** Join research and atomic/temporal routing to durable execution; complete admitted browser/network/tab operations, detached UI inference and actual model readiness. Add object memory through its existing dependency cut, including deletion and monitor gates before persistent user memory.
4. **Qualify learning, compatibility and release.** Preserve P111–P117 semantics, seven retrieval profiles and measured embeddings; run real pinned package/browser/provider workflows and frozen independent benchmarks. Optional trained deployments remain a separate later promotion decision.

Each closure record needs the source requirement, canonical stage and U owner, exact implementation revision, test/fixture or real-system evidence, supported/unsupported behavior, remaining blockers and rollback/migration impact. This documentation audit supplies requirements and mappings, not those implementation completion records.
