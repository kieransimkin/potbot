# Potbot frontend–backend contract v1 (proposal; backend track owns implementation)

This contract identifies missing interfaces; it **does not claim they already
exist** on the current Potbot API. Keep the Python backend authoritative.

## Authentication and session model

A Next.js server-side boundary must authenticate the human user and pass a
workspace-scoped access identity to Potbot. Never expose the service's private
bearer token through a `NEXT_PUBLIC_` variable or through HTML hydration. CSRF
protection is required for mutations, with SameSite/HttpOnly cookies, explicit
origin validation, rate limiting, session expiry and audit logging. A service
identity alone is **not** a multi-user login system.

### Graph projection

```ts
export type GraphNode = {
  id:string; parentId:string|null; label:string;
  state:'pending'|'running'|'completed'|'rejected'|'indeterminate';
  kind:'objective'|'hypothesis'|'task'|'evidence'|'result';
};
export type GraphEdge = { source:string; target:string; relation:string };
export type GraphProjection = { revision:number; nodes:GraphNode[]; edges:GraphEdge[] };
```

Graph visibility must not include hidden chain-of-thought, provider credentials
or sensitive prompts from another workspace. Expose task status, high-level
summaries, recorded evidence, verified tool output IDs, costs and provenance.
Require sequence-numbered event replay with monotonic revisions, overflow/gap
signalling and client resume support.

### Workspace isolation

- Every session, terminal, browser, model download and reasoning run is owned by
  one authenticated workspace/principal. Cross-workspace IDs must be rejected.
- Closing or minimizing a pane changes **UI visibility only**, never silently
  kills a running job, process or browser. Explicit termination is a separate
  audited action with its own capability.
- Large downloads and model installation report stage, bytes, expected total,
  rate, ETA where known, verification and cancellation status. Unknown ETA is
  `null`, not a fabricated timestamp.
- Workspaces must be discovered from the backend, not generated by frontend
  guessing. A separately labelled development demo is the sole synthetic mode.

## Current UI-1/UI-2 state

The frontend currently includes an explicitly activated synthetic demo at
`/?demo=1` in development only, typed projection interfaces, per-workspace
layout persistence, and closable panes for future resources. **It does not
send real prompts, execute tools, load workspaces, provide PTY input, control
browser sessions or show fake model-install progress.** Those are backend and
UI-3 through UI-6 deliverables.

## UI-3 bridge available in frontend (`main` backend unchanged)

The frontend now implements these **Next.js-only** routes, which are not a
new Potbot Python API and are not published directly on the Python server:

| Next.js route | Function |
| --- | --- |
| `GET /api/ui/auth/status` | Whether operator authentication is configured and active |
| `POST /api/ui/auth/login`, `/logout` | Same-origin login/logout; HttpOnly signed session cookie |
| `GET /api/ui/bootstrap` | Probe backend `/v1/models` and expose the **single configured** workspace |
| `POST /api/ui/chat` | Workspace-scoped streaming adapter to `/v1/chat/completions` |
| `GET /api/ui/reasoning/{run_id}?after=N` | Read safe checkpoint graph and cursor events from existing reasoning API |

The Next.js server is the **only** holder of its Potbot bearer token. It has no
separate directory of users, no multi-tenant authorization and no durable
message history. Real workspace discovery must eventually replace the
explicitly configured one-workspace fallback, rather than assuming this
frontend has authorized access to arbitrary IDs. New routes are client-facing,
not a replacement for Potbot backend-workspace ACLs.

### Existing upstream compatibility

- `POST /v1/chat/completions` responds with `text/event-stream`, OpenAI chat
  delta frames and `X-Potbot-Run-Id`, and can indicate an in-stream provider
  failure. UI-3 parses partial SSE frames and treats missing `[DONE]` as
  indeterminate, not success.
- `GET /v1/reasoning/{run_id}` returns a checkpoint including a `snapshot`
  object with `nodes` and `revision` when the reasoning store is configured.
  The Next.js bridge projects only public node labels, parent links, roles and
  states. It does not return private intermediate provider content.
- `GET /v1/reasoning/{run_id}/events?after=N&limit=200` provides monotonic
  event sequences. UI-3 **polls** those endpoints while a backend WebSocket
  graph-projection stream is still missing; it detects gaps and resets cursor.

### Remaining backend obligations (not represented as already implemented)

Authenticated multi-workspace discovery and switching, durable chat histories,
`/v1/reasoning/{run_id}/graph` as an authoritative typed projection, push graph
events with replay and gap detection, explicit typed steering actions, safe
workspace PTY, controlled browser sessions, download/model-install telemetry,
account preference persistence, distributed rate limiting and user access
management all remain open. No fake progress or browser/terminal controls are
exposed by the UI before those server facilities exist.

## UI-4 reasoning event projection (implemented on frontend bridge)

The existing Potbot backend event page `/v1/reasoning/{run_id}/events`
returns a list of `{sequence, type, data}`. The authenticated Next.js bridge
at `/api/ui/reasoning/{runId}?after=N` now returns `events` as a bounded list of
`{sequence:number, type:string}` alongside the current sanitized graph,
`cursor`, `gap`, `more`, `status`, and `latestTypes`. It **never** forwards
raw event `data`, prompt/result bodies, claim tokens or private billing details.
All values are scoped by the configured backend bearer token, with no
cross-workspace run enumeration. The event timeline uses sequence numbers
without fabricating times. Backend migration to a typed, push-based graph
stream must preserve strict workspace checks, continuity epochs, bounded
replay, and an explicit gap/resnapshot handshake.

## UI-8 routes backed by *existing* read-only Potbot services

These operator-authenticated Next.js projections are implemented and no
workspace selection is inferred from user-controlled query strings:

| Next.js endpoint | Backend source | Scope and output |
| --- | --- | --- |
| `GET /api/ui/activity?after=N` | `GET /v1/jobs?limit=50` and `GET /v1/jobs/events?after=N&limit=100` | Authenticated workspace only; whitelisted job state, stage, safe counts, timestamps and sequence-ordered event **types**. No job input, results, credentials, event data or cross-workspace query. |
| `GET /api/ui/models` | `GET /v1/models` | Identity, role, response protocol and explicit qualified/configured booleans. No assertion of installed weights or download progress. |

The backend's `model.generate` job cannot be presented as a file download.
Future transfer and installation routes require new backend implementation;
frontend UI placeholders cannot authorize installs or invent progress events.
