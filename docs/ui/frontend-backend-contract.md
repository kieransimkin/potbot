# Potbot frontend–backend contract v1 (proposal; backend track owns implementation)

This contract identifies missing interfaces; it **does not claim they already
exist** on the current Potbot API. Keep the Python backend authoritative.

## Authentication and session model

A Next.js server-side boundary must authenticate the human user and pass a
workspace-scoped access identity to Potbot. Never expose the service's private
bearer token through a `NEXT_PUBLIC_` variable or through HTML hydration. CSRF
protection is required for mutations, with SameSite/HttpOnly cookies, explicit
origin validation, rate limiting, session expiry and audit logging. A service
identity alone is **not** a multi-user login system.

### Graph projection

```ts
export type GraphNode = {
  id:string; parentId:string|null; label:string;
  state:'pending'|'running'|'completed'|'rejected'|'indeterminate';
  kind:'objective'|'hypothesis'|'task'|'evidence'|'result';
};
export type GraphEdge = { source:string; target:string; relation:string };
export type GraphProjection = { revision:number; nodes:GraphNode[]; edges:GraphEdge[] };
```

Graph visibility must not include hidden chain-of-thought, provider credentials
or sensitive prompts from another workspace. Expose task status, high-level
summaries, recorded evidence, verified tool output IDs, costs and provenance.
Require sequence-numbered event replay with monotonic revisions, overflow/gap
signalling and client resume support.

### Workspace isolation

- Every session, terminal, browser, model download and reasoning run is owned by
  one authenticated workspace/principal. Cross-workspace IDs must be rejected.
- Closing or minimizing a pane changes **UI visibility only**, never silently
  kills a running job, process or browser. Explicit termination is a separate
  audited action with its own capability.
- Large downloads and model installation report stage, bytes, expected total,
  rate, ETA where known, verification and cancellation status. Unknown ETA is
  `null`, not a fabricated timestamp.
- Workspaces must be discovered from the backend, not generated by frontend
  guessing. A separately labelled development demo is the sole synthetic mode.

## Current UI-1/UI-2 state

The frontend currently includes an explicitly activated synthetic demo at
`/?demo=1` in development only, typed projection interfaces, per-workspace
layout persistence, and closable panes for future resources. **It does not
send real prompts, execute tools, load workspaces, provide PTY input, control
browser sessions or show fake model-install progress.** Those are backend and
UI-3 through UI-6 deliverables.
